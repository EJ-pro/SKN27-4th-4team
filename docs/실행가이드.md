# 프로젝트 실행 가이드

이 프로젝트는 Django 단독 프로젝트가 아니라 다음 서비스가 함께 실행되는 구조입니다.

- Django backend: API 서버
- React/Vite frontend: 웹 화면
- PostgreSQL: 운동/루틴 저장 DB
- Neo4j: GraphDB 기반 운동 추천 후보 검색

따라서 `python manage.py runserver`만으로는 전체 화면과 추천 기능이 정상 실행되지 않습니다. 팀원 실행은 Docker 기준을 권장합니다.

## 1. 사전 준비

아래 프로그램이 설치되어 있어야 합니다.

- Git
- Docker Desktop
- DBeaver 선택 사항

Docker Desktop 실행 후 터미널에서 확인합니다.

```powershell
docker --version
docker compose version
```

## 2. 프로젝트 받기

```powershell
git clone https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN27-4th-4team.git
cd SKN27-4th-4team
```

작업 브랜치가 따로 있으면 해당 브랜치로 이동합니다.

```powershell
git checkout feature_yunjung_routine_recommend
git pull
```

## 3. `.env` 파일 준비

프로젝트 루트에 `.env` 파일이 필요합니다.

```text
SKN27-4th-4team/
  .env
  docker-compose.yml
  backend/
    recommendation_service/
    db/
    data/
  frontend/
  database/          ← Neo4j Docker 볼륨 (gitignore)
```

Docker 실행 기준 예시는 아래와 같습니다.

```env
# Database
DB_HOST=db
DB_PORT=5432
DB_NAME=routinegraph
DB_USER=postgres
DB_PASSWORD=yourpassword (비밀번호는 변경해주세요 ㅜ ㅠㅍ)

# Django
SECRET_KEY=django-insecure-change-me-in-production
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1

# LLM
OPENAI_API_KEY=여기에_키_입력
GROQ_API_KEY=여기에_키_입력
LLM_PROVIDER=groq
GROQ_MODEL=llama-3.1-8b-instant

# Neo4j
NEO4J_URI=bolt://neo4j:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=test1234
NEO4J_AUTH=neo4j/test1234
```

주의:

- 실제 API Key는 문서나 Git에 올리지 않습니다.
- Docker 기준 `DB_HOST`는 `db`입니다.
- Docker 기준 `NEO4J_URI`는 `bolt://neo4j:7687`입니다.
- 로컬에서 직접 Django를 실행할 때는 별도 설정이 필요합니다. 기본 실행은 Docker를 사용하세요.

## 4. Docker로 전체 실행

프로젝트 루트에서 실행합니다.

```powershell
docker compose up -d --build
```

상태 확인:

```powershell
docker compose ps
```

정상이라면 아래 컨테이너가 떠야 합니다.

- `routinegraph_frontend`
- `routinegraph_backend`
- `routinegraph_db`
- `neo4j`

## 5. 접속 주소

```text
프론트엔드: http://localhost:5173
백엔드 API: http://localhost:8000
Neo4j Browser: http://localhost:7474
```

Neo4j 로그인:

```text
ID: neo4j
PW: test1234
```

루틴 추천 화면:

```text
http://localhost:5173/routine
```

## 6. 추천 루틴 테스트 순서

1. 브라우저에서 `http://localhost:5173/routine` 접속
2. 설문 입력
3. `AI 추천 루틴 생성하기` 클릭
4. 추천 결과 확인
5. 수정 요청이 있으면 `추천 루틴 최종 검토` 영역에 입력
6. `수정 요청 보내기` 클릭
7. 변경사항 팝업 확인
8. 최종 OK이면 `승인하고 저장하기` 클릭
9. 저장된 루틴을 확인

## 7. DBeaver 연결 정보

PostgreSQL 확인용입니다.

```text
Host: localhost
Port: 5432
Database: routinegraph
User: postgres
Password: yourpassword
```

중요:

- `postgres` DB가 아니라 `routinegraph` DB에 접속해야 합니다.
- `weekly_schedulers does not exist` 오류가 나오면 보통 다른 DB에 접속한 것입니다.

확인용 SQL:

```sql
SELECT *
FROM public.weekly_schedulers
ORDER BY created_at DESC;
```

```sql
SELECT *
FROM public.daily_routines
ORDER BY scheduler_id DESC, scheduled_date, routine_order;
```

중복 확인:

```sql
SELECT device_uuid, year, week_number, COUNT(*) AS cnt
FROM public.weekly_schedulers
GROUP BY device_uuid, year, week_number
HAVING COUNT(*) > 1;
```

```sql
SELECT scheduler_id, scheduled_date, routine_order, COUNT(*) AS cnt
FROM public.daily_routines
GROUP BY scheduler_id, scheduled_date, routine_order
HAVING COUNT(*) > 1;
```

두 쿼리 결과가 비어 있으면 중복 저장은 없는 상태입니다.

## 8. 자주 나는 오류

### 8.1. `react-router-dom` import 오류

오류 예시:

```text
Failed to resolve import "react-router-dom" from "src/App.jsx"
```

원인:

- 프론트 의존성이 설치되지 않았거나 Docker frontend 이미지가 예전 상태입니다.

해결:

```powershell
docker compose build --no-cache frontend
docker compose up -d
```

그래도 안 되면:

```powershell
docker compose down
docker compose up -d --build
```

로컬 npm 실행이라면:

```powershell
cd frontend
npm install
npm run dev
```

### 8.2. DBeaver에서 `weekly_schedulers does not exist`

원인:

- `postgres` DB에 접속했을 가능성이 큽니다.

해결:

- DBeaver 연결 Database를 `routinegraph`로 바꿉니다.
- 쿼리에서 `public.weekly_schedulers`처럼 스키마를 명시합니다.

### 8.3. Django만 켰는데 화면이 안 뜸

정상입니다. 이 프로젝트 화면은 Django 템플릿이 아니라 React/Vite 프론트입니다.

전체 실행은 아래 방식으로 하세요.

```powershell
docker compose up -d --build
```

### 8.4. 추천 생성이 너무 오래 걸림

확인할 것:

- LLM API Key가 정상인지
- Neo4j가 켜져 있는지
- GraphDB 데이터가 들어 있는지
- 백엔드 로그에 에러가 있는지

로그 확인:

```powershell
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
docker compose logs --tail=100 neo4j
```

### 8.5. 다른 PC에서 같은 루틴이 보임

현재 임시 사용자 구분은 로그인 계정이 아니라 브라우저 `localStorage`의 `fitai_device_uuid` 기반입니다.

같은 `device_uuid`를 쓰면 같은 루틴이 조회될 수 있습니다.

브라우저 개발자도구에서 `localStorage`를 지우거나, 다른 브라우저/시크릿 창으로 테스트하면 다른 사용자처럼 동작합니다.

운영 수준으로는 로그인 사용자 기준 저장으로 바꾸는 것이 안전합니다.

## 9. 컨테이너 재시작/초기화

일반 재시작:

```powershell
docker compose restart
```

완전히 내렸다가 다시 실행:

```powershell
docker compose down
docker compose up -d --build
```

주의: 아래 명령은 DB 볼륨까지 삭제할 수 있습니다.

```powershell
docker compose down -v
```

데이터가 날아가도 되는 개발 초기화 상황에서만 사용하세요.

## 10. 로컬 직접 실행이 필요한 경우

권장하지는 않지만, Docker 대신 직접 실행해야 한다면 최소 3개를 따로 실행해야 합니다.

1. DB와 Neo4j 실행

```powershell
docker compose up -d db neo4j
```

2. 백엔드 실행

이 경우 `.env`를 로컬 기준으로 바꿔야 합니다.

```env
DB_HOST=localhost
NEO4J_URI=bolt://localhost:7687
```

```powershell
cd backend
python manage.py runserver
```

3. 프론트 실행

```powershell
cd frontend
npm install
npm run dev
```

접속:

```text
http://localhost:5173
```

팀원 실행 안내는 Docker 방식으로 통일하는 것을 권장합니다.
